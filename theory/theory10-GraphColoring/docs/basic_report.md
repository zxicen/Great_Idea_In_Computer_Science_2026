## 1 问答 Q1–Q3

**Q1：怎样判断给定染色是否合法？检查哪些边，复杂度是多少？**
先检查每个顶点都有颜色且取值在允许范围内（二染色为 {0,1}，三染色为 {0,1,2}），再**逐条边**检查两端颜色是否不同。检查对象是全部 m 条边（自环 `u==v` 必然同色，直接不合法）。每个顶点看一次、每条边看一次，时间 **O(n+m)**。代码见 `graph.py` 的 `is_valid_coloring`。

**Q2：为什么二染色可以用 BFS/DFS 完成？奇环为什么造成矛盾？**
二染色没有“选择”：每个连通分量里只要给起点定一种颜色，它的邻居必须是另一种颜色，邻居的邻居又必须回到第一种……整个分量的颜色被**唯一决定**，所以只需沿边传播，遇到两端同色就失败，不需要回溯。不连通时对每个未染色顶点重新作起点（孤立点直接染 0）。
奇环矛盾：沿环走一圈，颜色逐边交替；奇数条边之后回到起点时颜色必然与起点相反，但那是同一个顶点，所以无解。反过来，没有奇环的图一定可二染色（二分图）。
线性时间：每个顶点最多入队一次，每条边从两个端点各被检查一次，共 O(n+m)。

**Q3：三染色的回溯算法搜索什么，什么时候退回？撤销时恢复什么？**
搜索的是“部分染色方案”：按 0,1,…,n-1 的固定顺序给顶点选颜色，每个顶点依次试 0,1,2。颜色与某个**已染色**邻居相同就跳过；某个顶点三种颜色都不行（或其后的分支全部失败）就退回上一个顶点换下一个颜色。撤销分支时必须把 `coloring[v]` 恢复为 `UNCOLORED`，否则残留的颜色会污染后续所有分支（`stats["nodes"]` 是统计量，不回滚）。

**“有解”与“无解”的证据**：
- 有解：给出一个合法染色即可，用 Q1 的方法 O(n+m) 验证；
- 无解：必须覆盖或正确排除**所有**分支。K4 返回无解是因为搜索穷尽了全部 16 个节点；提前 `return None` 是错误的。

**NP 完全 ≠ 每个实例都难**：链、偶环、完全二分图 K(40,40) 上朴素回溯分别只要 n+1、n+1、81 个节点（见 `tests/test_oj_three_color.py`），而相变区的随机图可能搜几十万节点。

| 图 | 二染色 | 三染色（朴素回溯） | NODES | 说明 |
| --- | --- | --- | --- | --- |
| 三角形 K3 | 否（奇环） | `[0,1,2]` | 4 | 三个顶点两两相邻，必须三色 |
| 四边形 C4 | `[0,1,0,1]` | `[0,1,0,1]` | 5 | 偶环，二分图；v3 与 v0、v2 同色 0，取 1 |

### 2.1 三角形的回溯树（成功）

`dfs(v)` 表示给顶点 v 染色，括号内为已染色状态；颜色 `c` 冲突者标 ✗。

```text
dfs(0) #1
└─ v0=0 → dfs(1) #2
   ├─ v1=0 ✗（与 v0 同色）
   └─ v1=1 → dfs(2) #3
      ├─ v2=0 ✗（与 v0 同色）
      ├─ v2=1 ✗（与 v1 同色）
      └─ v2=2 → dfs(3) #4  v==n，成功
```

得到 `[0,1,2]`，NODES = 4，没有回溯。有解只需这一条路径作证据。

### 2.2 K4 的回溯树（失败，只画 v0=0 的子树）

```text
dfs(0) #1
├─ v0=0 → dfs(1) #2
│  ├─ v1=0 ✗
│  ├─ v1=1 → dfs(2) #3
│  │  ├─ v2=0 ✗  v2=1 ✗
│  │  └─ v2=2 → dfs(3) #4
│  │     └─ v3=0 ✗  v3=1 ✗  v3=2 ✗   ← 死路，回溯到 v2、v1
│  └─ v1=2 → dfs(2) #5
│     ├─ v2=0 ✗  v2=2 ✗
│     └─ v2=1 → dfs(3) #6
│        └─ v3=0 ✗  v3=1 ✗  v3=2 ✗   ← 死路
├─ v0=1 → …（与 v0=0 对称的 5 个节点）
└─ v0=2 → …（同样 5 个节点）
```

节点数 = 1 + 3 × 5 = 16。算法没有利用对称性，v0=1、v0=2 的子树要重新搜完才能确认无解——这就是“无解需要覆盖全部分支”。

## 3 朴素回溯伪代码

```text
three_color_backtrack(n, adj, stats):
    若存在自环 v ∈ adj[v]：返回 None            # 无法合法染色，不进入搜索
    coloring ← [UNCOLORED] × n

    dfs(v):                                       # 准备给顶点 v 染色
        stats.nodes += 1
        若 v == n：返回 成功
        对 c = 0, 1, 2：
            若 adj[v] 中存在已染色邻居 u 使 coloring[u] == c：跳过
            coloring[v] ← c
            若 dfs(v + 1) 成功：返回 成功
            coloring[v] ← UNCOLORED               # 撤销，回溯
        返回 失败

    返回 coloring 若 dfs(0) 成功，否则 None
```

二染色程序见 `src/solver.py` 的 `two_color`（BFS，约 15 行）。

## 4 指数爆炸实验

随机图（固定 seed 序列 2026…2045，每个规模 20 个实例取平均）、平均度数 4.7（m = round(4.7n/2)）：

| n | m | 可三染色比例 | 平均节点数 | 平均耗时 (ms) |
| --- | --- | --- | --- | --- |
| 10 | 24 | 0/20 | 141.6 | 0.14 |
| 12 | 28 | 0/20 | 377.2 | 0.37 |
| 14 | 33 | 1/20 | 727.1 | 0.72 |
| 16 | 38 | 0/20 | 1202.5 | 1.17 |
| 18 | 42 | 1/20 | 5285.2 | 5.06 |
| 20 | 47 | 1/20 | 8815.0 | 9.37 |
| 22 | 52 | 3/20 | 14180.5 | 13.85 |
| 24 | 56 | 1/20 | 27917.5 | 28.17 |
| 26 | 61 | 3/20 | 49883.6 | 50.91 |
| 28 | 66 | 4/20 | 96125.4 | 98.38 |

- 对 ln(节点数) 关于 n 做最小二乘拟合，节点数 ≈ c^n，**c ≈ 1.43**；n=20→28 的逐步增长率约 1.35。每增加 2 个顶点节点数约翻一番，趋势近似指数。
- 理论最坏规模 3^n：n=28 时 3^28 ≈ 2.3×10^13，而实测仅约 10^5，约为其 4×10^-9。**免费剪掉分支的是冲突检查**：一旦当前顶点与已染色邻居冲突，就立刻放弃以它为根的整棵子树，而不是等到染完所有顶点再检查。边越多，剪枝越早。
- 稀疏的链/偶环/二分图几乎不回溯（见 Basic 数据 NODES = n+1），“指数”只出现在有大量局部冲突又恰好无解/难解的实例上。

### 4.2 Mycielski（Grötzsch）图的启示

`data/mycielski4.txt` 无三角形，却需要 4 色，朴素回溯要搜 472 个节点才能确认无解。无解没有“一眼看出”的局部理由（如 K4），说明“难”不一定有显而易见的局部证据；而 NP 完全性正是“有解容易验证、无解/求解没有已知快速办法”——对 UNSAT 实例，我们没有比穷举更短的通用证据。
