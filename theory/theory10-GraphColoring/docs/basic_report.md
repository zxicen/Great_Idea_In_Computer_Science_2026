## 1 图的表示

图用**邻接表**保存：`adj[v]` 是顶点 v 邻居的 `set`，顶点编号 0..n-1，无向边 (u,v) 在 `adj[u]` 与 `adj[v]` 中各存一次。OJ 框架同样按这种方式读入。

| 表示 | 空间 | 判断 (u,v) 是否相邻 | 枚举 v 的邻居 | 适合 |
| --- | --- | --- | --- | --- |
| 邻接表（set 版，本项目） | O(n+m) | 期望 O(1) | O(deg v) | 稀疏图；回溯里的冲突检查只需遍历 `adj[v]` |
| 邻接矩阵 | O(n²) | O(1) | O(n) | 稠密图；n=500 时矩阵 25 万格，浪费且遍历邻居更慢 |
| 边列表 | O(m) | O(m) | O(m) | 只做一次性遍历 |

选 set 而不是 list，是因为输入保证无重边，用集合顺带去重，并让“是否相邻”的查询是 O(1)。图文件格式为第一行 `n m`，之后 m 行每行一条边，`#` 开头为注释（`data/` 下文件即此格式）。

自环（u==v）会让 `adj[u]` 含 u 自身：它必然不合法，二染色会在“同色相邻”处自然发现，三染色的冲突检查只看**已染色**邻居，发现不了，所以 `three_color_backtrack` 在搜索前单独检查自环并返回 `None`；OJ 框架则由 `main()` 直接输出 `UNSAT` 与 `NODES 0`。

## 2 问答 Q1–Q3

**Q1：怎样判断给定染色是否合法？检查哪些边，复杂度是多少？**
先检查每个顶点都有颜色且取值在允许范围内（二染色为 {0,1}，三染色为 {0,1,2}），再**逐条边**检查两端颜色是否不同。检查对象是全部 m 条边（自环 `u==v` 必然同色，直接不合法）。每个顶点看一次、每条边看一次，时间 **O(n+m)**。助教提供的 `graph.py` 里的 `is_valid_coloring` 即此逻辑；`gen_basic_data.py` 对 5 个手工图的结果、OJ 本地测试对每个 SAT 输出都用它做了合法性检查。这一点还说明三染色属于 **NP**：给出方案后验证只要线性时间。

**Q2：为什么二染色可以用 BFS/DFS 完成？奇环为什么造成矛盾？**

*没有选择。* 每个连通分量里只要给起点定一种颜色，它的邻居必须是另一种颜色，邻居的邻居又必须回到第一种……整个分量的颜色被**唯一决定**，所以只需沿边传播，遇到两端同色就失败，不需要回溯。不连通时对每个未染色顶点重新作起点（孤立点直接染 0）。

*奇环矛盾。* 沿环走一圈，颜色逐边交替；奇数条边之后回到起点时颜色必然与起点相反，但那是同一个顶点，所以无解。反过来，没有奇环的图一定可二染色（二分图）。

*BFS 版的正确性。*
- **可靠性**（返回染色则它合法）：每个顶点出队时检查它的全部邻边——邻居未染则染成相反色，已染则比较，同色即返回 `None`。每条边会被它的两个端点各检查一次，所以如果算法正常结束，每条边两端异色。
- **完备性**（返回 `None` 则图里有奇环）：BFS 中顶点的颜色等于它在 BFS 树里深度的奇偶。若发现边 (u,v) 同色，则 u、v 深度奇偶相同。从它们在 BFS 树里的最近公共祖先分别走到 u 和 v，再加上边 (u,v)，得到一个环，长度 = 两段树路径长度之和 + 1；两段长度各等于 d(u)−d(a)、d(v)−d(a)，其和 d(u)+d(v)−2d(a) 为偶数，所以环长为奇数。
- **复杂度**：每个顶点最多入队一次，每条边从两个端点各被检查一次，共 **O(n+m)**；颜色数组 O(n)，队列 O(n)。

**Q3：三染色的回溯算法搜索什么，什么时候退回？撤销时恢复什么？**

搜索的是“部分染色方案”：按 0,1,…,n-1 的固定顺序给顶点选颜色，每个顶点依次试 0,1,2。颜色与某个**已染色**邻居相同就跳过；某个顶点三种颜色都不行（或其后的分支全部失败）就退回上一个顶点换下一个颜色。撤销分支时必须把 `coloring[v]` 恢复为 `UNCOLORED`，否则残留的颜色会污染后续所有分支（`stats["nodes"]` 是统计量，不回滚）。

*不变式与正确性。* 记 `dfs(v)` 的前置条件为“顶点 0..v-1 已得到一个合法的部分染色，顶点 v..n-1 都是 `UNCOLORED`”。对 v 从 n 倒推归纳：
- v = n：全部染完，返回成功；
- v < n：`dfs(v)` 返回成功，当且仅当存在某个与 0..v-1 现有颜色不冲突的颜色 c，使 `dfs(v+1)` 成功。由归纳假设，这等价于“0..v-1 的现有染色能扩展成整个图的合法三染色”。
- 每个分支失败返回时，`coloring[v]` 都恢复为 `UNCOLORED`，所以兄弟分支看到的状态与第一次进入时一致。

因此 `dfs(0)` 成功当且仅当图可三染色，且成功时的 `coloring` 就是按固定顺序找到的第一个合法方案。

*“有解”与“无解”的证据。*
- 有解：给出一个合法染色即可，用 Q1 的方法 O(n+m) 验证；
- 无解：必须覆盖或正确排除**所有**分支。K4 返回无解是因为搜索穷尽了全部 16 个节点；提前 `return None` 是错误的。

*复杂度。* 递归深度为 n+1；每个节点做至多 3 次冲突检查，每次遍历 `adj[v]`，所以单个节点代价 O(deg v)。节点数上界为 Σ_{k=0..n} 3^k = (3^(n+1) − 1)/2，因此最坏时间 **O(3^n · Δ)**（Δ 为最大度数），额外空间 O(n)。

**NP 完全 ≠ 每个实例都难。** 链、偶环、完全二分图 K(40,40) 上朴素回溯分别只要 n+1、n+1、81 个节点（OJ 本地测试点 13–15 记录于 `results/test_record.txt`），因为每个顶点第一次选的颜色就不冲突，从不回溯；而相变区的随机图可能搜几十万节点。有趣的对照是 K5：它的节点数和 K4 一样是 16，因为前 4 个顶点已经构成 K4，搜索在第 5 个顶点之前就把一切分支排除了。

### 3.1 三角形的回溯树（成功）

`dfs(v)` 表示给顶点 v 染色，颜色 `c` 冲突者标 ✗，`#k` 为第 k 次进入。

```text
dfs(0) #1
└─ v0=0 → dfs(1) #2
   ├─ v1=0 ✗（与 v0 同色）
   └─ v1=1 → dfs(2) #3
      ├─ v2=0 ✗（与 v0 同色）
      ├─ v2=1 ✗（与 v1 同色）
      └─ v2=2 → dfs(3) #4  v==n，成功
```

得到 `[0,1,2]`，NODES = 4，没有回溯。有解只需这一条路径作证据。

### 3.2 K4 的回溯树（失败，只画 v0=0 的子树）

```text
dfs(0) #1
├─ v0=0 → dfs(1) #2
│  ├─ v1=0 ✗
│  ├─ v1=1 → dfs(2) #3
│  │  ├─ v2=0 ✗  v2=1 ✗
│  │  └─ v2=2 → dfs(3) #4
│  │     └─ v3=0 ✗  v3=1 ✗  v3=2 ✗   ← 死路，回溯到 v2、v1
│  └─ v1=2 → dfs(2) #5
│     ├─ v2=0 ✗  v2=2 ✗
│     └─ v2=1 → dfs(3) #6
│        └─ v3=0 ✗  v3=1 ✗  v3=2 ✗   ← 死路
├─ v0=1 → …（与 v0=0 对称的 5 个节点）
└─ v0=2 → …（同样 5 个节点）
```

节点数 = 1 + 3 × 5 = 16。算法没有利用对称性，v0=1、v0=2 的子树要重新搜完才能确认无解——这就是“无解需要覆盖全部分支”。

## 4 朴素回溯伪代码

```text
three_color_backtrack(n, adj, stats):
    若存在自环 v ∈ adj[v]：返回 None            # 无法合法染色，不进入搜索
    coloring ← [UNCOLORED] × n

    dfs(v):                                       # 准备给顶点 v 染色
        stats.nodes += 1
        若 v == n：返回 成功
        对 c = 0, 1, 2：
            若 adj[v] 中存在已染色邻居 u 使 coloring[u] == c：跳过
            coloring[v] ← c
            若 dfs(v + 1) 成功：返回 成功
            coloring[v] ← UNCOLORED               # 撤销，回溯
        返回 失败

    返回 coloring 若 dfs(0) 成功，否则 None
```

二染色（`two_color`）：

```text
two_color(n, adj):
    coloring ← [UNCOLORED] × n
    对每个 s = 0..n-1 且 coloring[s] 未染色：       # 处理每个连通分量
        coloring[s] ← 0；队列 ← [s]
        当队列非空：
            u ← 出队
            对 v ∈ adj[u]：
                若 coloring[v] 未染色：coloring[v] ← 1 − coloring[u]；入队
                否则若 coloring[v] == coloring[u]：返回 None   # 同色相邻（含自环）：奇环
    返回 coloring
```

## 5 OJ 提交文件与本地验收

`include/src/three_color.py` 是 OJ 单文件（Python 3）：我只填写 `three_color(n, adj) -> (coloring, nodes)`，输入解析、自环判断和输出由框架提供。题目规则完全钉死，以保证所有正确程序输出一致：

- 顶点按 0..n-1 的顺序染色，每个顶点按颜色 0,1,2 的顺序试；
- 只与**已染色**邻居判冲突，不向前看；
- `NODES` 为进入 `dfs` 的总次数，首次调用 `dfs(0)` 和终止调用 `dfs(n)` 都计入；
- 找到第一个完整方案立即停止；
- 输出格式：可染时 `SAT` / 颜色序列 / `NODES x`，不可染时 `UNSAT` / `NODES x`，评测全文精确比较；
- 递归深度可达 n+1（n ≤ 500），框架已把递归上限提到 10⁶；自环由 `main()` 拦截，输出 `UNSAT`、`NODES 0`。

### 7.1 增长趋势

- 对 ln(平均节点数) 关于 n 做最小二乘拟合，节点数 ≈ c^n，**c ≈ 1.43**；n=20→28 的逐顶点增长率约 1.35，即每加 2 个顶点节点数约为原来的 1.8 倍。趋势近似指数，但底数远小于 3。
- 相邻规模的比值不均匀（例如 16→18 一步增长 4.4 倍，其余多在 1.6–2.7 倍）。每个规模只有 20 个实例，而节点数是重尾分布，个别难实例会明显拉高平均值，所以单步比值不稳定，拟合斜率更可信。
- 耗时与节点数几乎成正比（约 1 微秒/节点量级，随机器变化），说明节点数是合理的性能度量。

### 7.2 谁在“免费”剪枝？

理论最坏规模 3^n：n=28 时 3^28 ≈ 2.3×10¹³，而实测仅约 9.6×10⁴，约为其 4×10⁻⁹。**免费剪掉分支的是冲突检查**：一旦当前顶点与已染色邻居冲突，就立刻放弃以它为根的整棵子树，而不是等到染完所有顶点再检查。边越多，剪枝越早。稀疏的链/偶环/二分图几乎不回溯（NODES = n+1），“指数”只出现在有大量局部冲突又恰好无解/难解的实例上。

如实记录：
- 难度**先升后降**——平均节点数在平均度数 4 附近最大，中位数的峰值在 4.5 附近，都落在“可染/不可染”的分界一带；太稀疏时多数实例一路贪心即可，太稠密时很快遇到冲突而被剪掉。
- 稀疏端平均值被个别重尾实例拉高（度数 2 的均值 62933 对应中位数 31，最大值约 169 万），所以应同时看中位数与最大值。
- 大 n 随机图三染色的可满足性阈值在平均度数约 4.69 附近；本实验 n 只有 30，可染比例下降得更早（度数 4 时已只有 17/30），这是有限规模效应，**不能当作对阈值的验证**。这是进阶部分“相变实验”的入口，本文不做深入。

## 8 Mycielski（Grötzsch）图的启示

`data/mycielski4.txt` 无三角形，却需要 4 色，朴素回溯要搜 472 个节点才能确认无解。无解没有“一眼看出”的局部理由（如 K4），说明“难”不一定有显而易见的局部证据；而 NP 完全性正是“有解容易验证、无解/求解没有已知快速办法”——对 UNSAT 实例，我们没有比穷举更短的通用证据。只看局部结构的启发式（例如“有没有三角形”）对它无效，这也是第 9 节展示最后引向 MRV 与前向检查的动机。
